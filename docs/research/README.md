# Research｜科学问题与证据（科研型项目按需）

工程型任务关注可靠实现与交接；科研型任务额外回答：什么方法有效、为什么、与谁比较、能否泛化。两者共用 Task、Dev、Design、Experiments；本页是一个轻量研究计划入口，不要求每个问题建立文件夹。已有实验协议、笔记、论文草稿或文献管理工具可作为等价来源。

## 研究计划（待实例化）

| 内容 | 填写原则 |
| --- | --- |
| Research question | 一个能通过证据回答的问题，不把工程功能当论文贡献 |
| Hypothesis | 可证伪假设，预先说明反例和可能的替代解释 |
| Prior work / baseline | 调查成熟实践和最强合理对照；文献清单按需，不强制资料库 |
| Protocol | 明确自变量、控制变量、数据/场景划分、资源预算、指标、停止规则与评价版本 |
| Evidence | 实验 Run ID、源码/数据/配置/种子、原始记录及不确定性；详见 Experiments |
| Findings | 正负结果、效应量/波动、失败归因、泛化范围、替代解释与结论强度 |
| Paper / dissemination | 按需记录潜在贡献、限制、复现材料；尚无结果不先写成功结论 |

在关键实验前冻结比较协议（记录版本）；事后探索需标注。优先小成本、能区分假设的判别实验。若主要结论依赖统计估计，记录独立重复、分割方式、方差/置信区间及合理样本量，避免挑选成功样本或在测试集调参。不用强制目录替代科学方法。

## 示例：如何从工程任务转为研究问题

- Real-to-Sim：不只问“是否能生成场景”，而是比较不同方法的物理有效性、成本、扩展性及训练/迁移效果；明确几何精度不等于接触动力学正确。候选假设及基线待项目立项。
- VLA/RL：不只问“是否成功一次”，而是比较近零初始成功率下的训练信号、失败数据利用与预算效率，以及未见场景的泛化表现。区分任务完成率、样本/算力预算及失败类型，控制初始模型与数据；研究结论待实测。

以上是研究问题示例，不表示项目已创建或已有实验成果。
