# Experiments

实验声明需要可追溯证据；独立目录是推荐形式，可引用项目现有可访问的实验系统。

尚无真实科研实验。重要实验记录 Run ID、commit、后端、资产/环境实际版本路径、配置、种子、资源实测、命令、输出及验收。区分 Mock、CPU、MuJoCo、PhysX、实机。保留失败；不同 episode 不拼接为整体成功。CI 与模板 smoke 仅为软件验证。真实实验数据及缓存保存在个人或经指定的数据区。

## 本模板的实际软件收据

`./run.sh smoke` 输出 JSON，包括收据 schema、Run ID、UTC 时间、检查耗时、Python 版本、输入配置 SHA-256、观察到的 Git commit/dirty 状态、验证层级、后端及状态。无可确认的 Git 身份时标 UNKNOWN；正式共享解释器运行模式不查询 Git。源码快照的正式身份应由经过验证的发布清单提供，不推断。收据不包含 GPU 或物理成功：scientific_result 始终为 NOT_TESTED。

需要留存时，将 JSON 输出保存到个人实验目录；不要写入共享正式源码。真实项目可以使用既有记录系统，不要求采用本示例收据 schema。

## 实验对照与端到端验证（适用时）

- 对照实验固定模型/checkpoint、数据版本、任务/初态、种子、最大步数、评价指标与评分版本；建议用协议 ID 或指纹记录同条件比较。快速抽样、完整 benchmark、真实部署不能混为一谈。
- 数据转换记录源输入标识、变换参数、schema 和时间/单位语义；用原生消费者重读，并针对关键字段、边界帧、缺失数据或失败情况验证。
- 训练→评测→部署链路应明确使用的同一 checkpoint 与各自的运行条件；短跑只证明流程，不证明模型效果。区分历史记录、当前重跑、在线决策和固定回放。
- 重要原生运行保存实际启动参数、资源、进程退出和运行结果，避免将服务在线、视频可播放或合成测试称为真实任务成功。
