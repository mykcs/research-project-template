# 交接验收

交接判断的是接手者能否继续工作，并满足最小统一目录要求，不是是否复制了所有模板文件。以下内容必须具备或按实际条件适用；现有 README、文档、工具、实验系统均可作为等价证据。

| 验收内容 | 状态与证据 |
| --- | --- |
| 必需：现行自有研究源码位于根目录 `src/`，旧入口仅委派，迁移后的实际运行和测试有证据 | 待实例化 |
| 条件必需：附网站时网站源代码及构建配置位于根目录 `website/`，有独立构建验证 | 待判定 |
| 必需：项目目标、上游关系、当前能力和验收边界可发现 | 待实例化 |
| 必需：当前未完成任务、阻碍、下一步及维护/反馈渠道可发现 | 待实例化 |
| 必需：接手者可独立定位源码、运行环境、启动命令及预期结果 | 待实例化 |
| 必需：可运行低成本检查并知道如何在个人分支开发、测试、PR | 待实例化 |
| 必需：Dev 已说明实际验证/CI 合同和执行状态 | 待实例化 |
| 条件必需：实际服务器、公共环境、GPU、资产、资源和发布信息可发现 | 待判定 |
| 条件必需：已有实验声明有真实证据和可复现条件；重要接口/假设可发现 | 待判定 |
| 必需：接手人员独立验证，明确通过、失败、阻塞或不适用 | 尚未执行 |

已有代表性成功实验需独立复现；没有成功实验则明确标记，并复现当前可运行检查或失败情况。无法运行时说明缺失条件，不伪造复现通过。科研完成与交接完成分别判定。

不要求固定文件名、文件数量、资料参考库、Wish、独立 ADR、专门归档目录或固定 CI 厂商。重要信息能找到并有效即可。模板中的空白待填项本身不构成交接完成。

## 首次使用的真实证据（推荐）

用干净 checkout（不复用原开发者的 .venv）执行 README 的首次运行命令，记录 commit、环境、命令、实际结果和缺失条件。随后检查日常预检是否需要额外安装。已有项目可以使用等价方式，仍按交接结果以及强制源码/网站位置验收。


辅助 audit 检查非空 src/ 与常见根目录网站框架配置，并提示可发现性和 Git 卫生；现行源码是否全部归位、其他网站框架及实际构建仍须审阅，handoff_readiness=NOT_VERIFIED；不能替代接手者本人实际验收。
